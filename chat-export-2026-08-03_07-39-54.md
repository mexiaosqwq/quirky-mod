- 刃只有 3px 亮部（255/190/68）+1px 轮廓。**在 α=240 的 `#100010` 背景上，`@`(24) 与背景灰阶差 <10，等于没画**。所以这把剑视觉宽度实测是 3px 亮 + 1px 软暗边。若你觉得刃偏细，把每行的 `@` 换成 `#`、原 `#` 换成 `d`(107)，即得到"真 4px 可见刃"，不改布局。

## 二、其余 5 个图标的统一规范 + 网格

### 统一硬规则（6 图共用）

1. **光源固定左上 45°**：每个形体 = `1px 高光(L1) + n px 本体(L2) + 1px 暗部(L3)`，暗部永远在右/下。
2. **笔画最小 2px**，主形体 ≥3px。禁止任何 1px 孤立笔画（血槽、铆钉、鞋带扣、多面切割线）。
3. **黑色(`@`)只做内部分隔**，永不描外轮廓（外轮廓黑 = 浪费像素，见第三节）。
4. **亮度阶梯必须跳档 ≥60 灰阶**。所以暗部二级用 `24 / 107`，**不要用 `24 / 68`**（差 44，深底上并成一团）。
5. **L1 高光像素数控制在 4–8px**，超了整行发白、抢右侧白色数值文本。
6. **视觉重心统一落在 row 6.5**（文本绘制在 y+3，8px 高，占 row 3–10），下面 5 个网格已按此对齐。
7. **col 15 永远空，col 14 只允许暗部**（右侧只有 2px 到文字）。

## 三、16×16 + 深底 + 14px 行高：什么会失效，怎么取舍

先纠正一个常见误判：**MC GUI 是整数倍最近邻放大，GUI atlas 无 mipmap，像素不会被插值"糊掉"**。真正会失效的是下面这几类，机制不同、对策不同：

1. **外轮廓黑边完全失效。** tooltip 背景 `0xF0100010`（α=240，仅 6% 透世界），实际背景亮度约 16–20。`@`=24 与之差 <10 灰阶 → 描在外轮廓上等于画透明。**对策：外轮廓靠 L1/L2 的亮度对比立形；`@` 只用于被亮像素包夹的内部分隔（胸甲中缝、靴底缝）。**
2. **`68` 与 `24` 相邻会并块。** 差 44 灰阶，在暗背景下人眼分不开。剑刃的 `#@` 就是这种情况（已在第一节说明并给出替换方案）。**需要两级暗部时用 `24 / 107`。**
3. **1px 孤立笔画读成噪点。** 血槽、铠甲铆钉、靴带、宝石的第二条切割线、箭头尾部的速度虚线——这些在 16px 下不是"细节"，是脏点。**能删就删；必须保留则加粗到 2px 或把对比拉到 ≥100 灰阶。**
4. **垂直方向真实可用只有 14px。** 行高 14 而图标 16：图标 N 的 row 14–15 会压在图标 N+1 的 row 0–1 上。**row 14/15 强制透明**（row 0 可用，前提是上一个图标遵守此规则——所以剑尖占 row 0 是安全的）。
5. **上下相邻 6 行会互相干扰重心。** 图标重心不在 row 6.5 附近时，那一行会看起来"图标和数字没对齐"。上面 5 个网格已统一到 6.5；剑本身也是 6.5。
6. **右边距只有 2px。** col 15 出现亮像素会和白色文本粘连；col 14 只放暗部。
7. **半透明边缘像素禁止。** 任何 alpha 介于 1–254 的像素都会与 `#100010` 混合出偏冷的灰边，正是旧版"灰扑扑"的来源。**只用 0 / 255。**

取舍优先级（16×16 里只能保三样）：**轮廓语义 > 光源一致性 > 材质细节**。也就是：先保证眯眼能认出"剑/闪电/甲/宝石/箭/靴"，再保证 6 个图标高光都在左上，材质纹理一律放弃。

## 替代方案（若主方案实测不满意）

- **击退**：现方案是纯箭头。若与"移速"语义混淆，可在 cols 0–1 的 r5–r8 加一条 2×4 `o` 竖条（"受力面"），代价 +8px 重量，且左边距归零。
- **移速**：若棕色靴子在深底上仍显闷，整套换铁靴配色（`W/M/#` + `d` 鞋底），代价是与"伤害/护甲"同为铁灰、6 行区分度下降——建议保留皮革棕。
- **胸甲/钻石**：若光学重量压过其他 4 个，优先削钻石（收 2px 宽）而非胸甲，因为胸甲的宽肩是它唯一的识别特征。

无法在此确认的一点：以上颜色在你实际 GUI scale 与显示器伽马下的观感。建议先只生成 `attack_speed` 和 `movement`（最亮与最暗两端）入游戏截图对比，确认亮度阶梯后再批量出全套。
