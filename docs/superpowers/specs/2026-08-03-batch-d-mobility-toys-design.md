# 批 D 设计文档 — 机动与玩具

日期：2026-08-03
状态：待用户审阅
定调：实用、不影响平衡、轻量；每个机制必须有音效/粒子/反馈等手感细节。

## 1. 绳捆（Rope）

### 1.1 定位

可从上往下铺的攀爬绳：站在高处往脚下放绳，一路垂到地面，爬绳上下。探洞、下矿、树屋的轻量机动工具。参考 Quark ropes，但按 Quirky"简单优先"裁剪：**不做投掷铺设弹道，只保留"向下延伸"核心体验**。

### 1.2 方块行为

- 新方块 `quirky:rope`：
  - **无碰撞箱**（可穿过），**可攀爬**：加入 `#minecraft:climbable` block tag（玩家贴绳按住前进即可爬，机制与藤蔓一致——项目自动爬梯已验证该 tag 路径）。
  - 视觉：一格高的麻绳段，细绳居中垂直贯穿（贴图：绳结纹理；模型：cross 型或细柱型，计划阶段择一，预览确认后落地）。
  - 光照透明、不阻挡视线，可含水（waterlogged 属性，水流中照常垂挂）。
- **支撑规则**：绳必须悬挂在"完整固体方块底部"或"另一段绳"之下；失去支撑时**自下而上连锁掉落为物品**（一段段掉，带掉落音效——手感细节）。
- **放置规则**：
  - 对固体方块底面右键 → 在其下方放一段绳。
  - **对已有绳段右键（手持绳）** → 在其正下方延伸一段（下方为空气时）；这是"一路往下铺"的主操作。
  - **潜行+对绳段右键** → 一次性把绳铺到最近的落地处或耗尽手持数量（上限 32 段/次，防手滑铺穿世界底）。
- **破坏**：打哪段掉哪段；上方的绳若因此失去支撑则连锁掉落。

### 1.3 音效与粒子

| 事件 | 反馈 |
|---|---|
| 放置/延伸 | `BLOCK_WOOL_PLACE` 类软质音效（音量 0.6，音高随延伸次数轻微递降，"一段段放绳"的节奏感） |
| 连锁掉落 | 每段 `BLOCK_WOOL_BREAK`（音量 0.4）+ 少量线状粒子（`ITEM` 粒子用线物品） |
| 攀爬 | 原版藤蔓/梯子攀爬音效天然生效（climbable tag 附带），不额外加 |
| 批量铺绳 | 快速连续的放置音（每段间隔 1 tick 播放，形成"唰——"的下滑声） |

### 1.4 配方

- 线×3（竖列）→ 绳×3。线易得（蜘蛛/羊毛），符合消耗品定位。

### 1.5 边界场景清单

| 场景 | 行为 |
|---|---|
| 延伸时下方是方块/水 | 水是允许延伸的（绳可含水）；固体方块则停止 |
| 铺绳路径中有半砖/梯子等 | 撞到任何非空气非水方块停止 |
| 支撑方块被活塞推走 | neighbor update 触发支撑检查 → 连锁掉落 |
| 绳上挂着玩家时被打断 | 玩家自然坠落（无碰撞箱，无特殊处理） |
| 创造模式批量铺 | 不消耗数量，但仍受 32 段/次上限 |
| 两个绳柱相邻 | 互不影响，各自独立支撑链 |
| 世界底部（y=-64） | 铺到最低层停止 |

### 1.6 配置

- `ropeEnabled`（bool，默认 true）
- `ropeMaxExtendPerUse`（int，1-64，默认 32）

### 1.7 实现要点与风险

- 新方块 + BlockItem + tag 文件（`data/minecraft/tags/block/climbable.json` 追加 `quirky:rope`——注意是**合并**进该 tag 的新文件，不是覆盖；数据包 namespace 用 `minecraft` tag 路径加入自有方块是标准做法）。
- 连锁掉落逻辑抽纯函数（输入：世界列快照；输出：应掉落的段列表），单测覆盖。
- 风险点：
  - `climbable` tag 在单测环境无数据包数据（项目已验证教训）——攀爬行为只能桌面客户端手动验证。
  - 支撑检查时机：`neighborChanged` + 放置后 tick 双保险。
- 贴图/模型先示意稿后落地。

### 1.8 验证

- 单测：支撑判定、连锁掉落段计算、批量铺设停止条件。
- 手动：桌面客户端放置/延伸/批量铺/攀爬/打断连锁/含水。

## 2. 回旋镖（Boomerang）

### 2.1 定位

投掷后飞回手中的玩具：飞行路径上**拾取地面物品**带给玩家（主要用途），对触碰生物造成轻微伤害+击退（次要，玩具级）。参考 Quark boomerang，伤害压到玩具水平，定位是拾取工具而非武器。

### 2.2 行为

- 新物品 `quirky:boomerang`：堆叠 1，耐久 **250**（每次完整飞行消耗 1 点），可被铁砧用木材修复。
- **投掷**：主手右键 → 生成 `quirky:boomerang` 实体，沿视线方向飞出：
  - 出手速度 1.0，**无重力**，飞行路径带轻微右偏弧线（回旋镖特征，偏移量小，约每格 0.03 弧度）。
  - 最大飞行距离 **12 格**（约 1.2 秒）后进入返程。
  - 飞行中旋转（客户端模型绕轴自转，每秒约 4 圈）。
- **返程**：达到最大距离或撞到方块后掉头，沿曲线飞回投掷者当前位置（追踪活玩家）：
  - 回到投掷者 1 格内 → 收回：若投掷者手/背包有空位则入包（优先原手持槽），否则掉落在玩家脚下。
  - 投掷者已死亡/离线 → 在实体当前位置掉落为物品。
- **拾取**：飞行实体触碰地面物品实体（0.5 格内）时将其吸收（记入实体 NBT），返航回收时一次性进玩家包（满则掉落）。吸收播放拾取音效。
- **伤害**：触碰生物造成 **2 点（1 心）伤害** + 小击退（0.3），每个生物每次飞行只判定一次（防持续刮擦连击）；对投掷者本人无伤害（返程穿过自己不受击）。
- 实体免疫火焰/箭矢等伤害，存在上限 10 秒兜底自毁（掉落物品）。

### 2.3 音效与粒子

| 事件 | 反馈 |
|---|---|
| 投掷 | `ENTITY_ARROW_SHOOT` 变体（音高 0.8，更"呼"的挥出感） |
| 飞行中 | 低音量嗡鸣循环？——**不做循环音**（容易吵），只保留投掷/命中/回收三类瞬时音效 |
| 命中生物 | `ENTITY_PLAYER_ATTACK_WEAK_SWEEP`（音量 0.5）+ 原版伤害粒子 |
| 撞到方块 | `BLOCK_WOOD_HIT`（音量 0.4） |
| 吸收物品 | `ENTITY_ITEM_PICKUP`（音量 0.5） |
| 回收到手 | `ITEM_ARMOR_EQUIP_GENERIC`（音量 0.5） |

### 2.4 配方与贴图/模型

- 合成：木棍×2 + 羽毛×1（形状合成，V 型摆放），廉价玩具。
- 物品贴图：木质 V 型回旋镖（先示意稿后落地）；实体用同款贴图做简单平面模型（`builtin/entity` 渲染或单层 JSON 模型，计划阶段定，以"飞行中可辨认旋转"为验收标准）。

### 2.5 边界场景清单

| 场景 | 行为 |
|---|---|
| 飞行中再次右键 | 手中已无回旋镖（投出即离手），无动作 |
| 回旋镖耐久归零 | 投出落地后不回收，直接损坏消失（`ITEM_BREAK` 音效+粒子） |
| 投掷进虚空/世界外 | 10 秒兜底自毁，不掉落（防虚空物品堆积） |
| 吸收的物品很多 | 实体 NBT 列表无上限压力（一次飞行路径有限），回收时满包部分掉落 |
| 命中盔甲架/展示框 | 视为生物路径之外：不伤害（只 LivingEntity），穿过 |
| 水中投掷 | 照常飞（无重力无阻力），不做水体特判 |
| 多人服命中别人 | 正常 2 点伤害（玩具级，PVP 无平衡影响）；归属记投掷者（死亡消息正确） |
| 飞行中投掷者传送走 | 返程追踪最新位置；跨维度则就地掉落 |

### 2.6 配置

- `boomerangEnabled`（bool，默认 true）
- `boomerangRange`（int，4-24 格，默认 12）
- `boomerangDamage`（int，0-4，默认 2）——设 0 可做纯拾取玩具

### 2.7 实现要点与风险

- 新实体注册进 `ModEntities`（参照 TorchArrowEntity 注册模式）；物品+实体渲染走新物品双文件清单+实体渲染器注册。
- 飞行物理自实现（tick 内位置积分+返程转向），不依赖原版弹射物基类（避免 AbstractArrow 的重力/pickup 语义污染）。
- "每生物每次飞行只伤一次"：实体持 `Set<UUID>`（NBT 序列化）。
- 风险点：
  - 客户端模型旋转渲染 + 实体位置插值（项目教训：视觉位置=实体位置必须一致，用实体的实际位置驱动渲染）。
  - 返程追踪活玩家：`Entity` 引用用 UUID 查找，防内存悬挂。
- 伤害走 `hurtServer`（26.2 服务端伤害 API，参考 docs/26.2-mechanics-notes.md）。

### 2.8 验证

- 单测：飞行步进/返程转向纯数学函数、命中去重集合逻辑、回收槽位选择。
- 手动：桌面客户端投掷手感（弧线/旋转/回收）、拾取、命中一次判定、耐久损坏、满包掉落。

## 3. 公共约定与批内顺序

- 新方块/物品过 `quirky-new-item-checklist`（方块对照现有 `wooden_hopper` 资源结构）；mixin 过 `quirky-mixin-runtime-audit`。
- **批内顺序建议**：绳捆（纯方块，风险低）→ 回旋镖（自定义实体+渲染，批内最重，放最后）。
- 非目标：回旋镖不做附魔（急速/范围）、绳不做横向悬挂/装饰绳。
