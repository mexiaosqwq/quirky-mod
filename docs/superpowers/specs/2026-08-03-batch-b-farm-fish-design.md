# 批 B 设计文档 — 田园渔猎

日期：2026-08-03
状态：待用户审阅
定调：实用、不影响平衡、轻量；每个机制必须有音效/粒子/反馈等手感细节。

## 1. 播种袋（Seed Pouch）

### 1.1 定位

手持右键耕地，一次批量播撒种子。与已有的收割补种机制（`harvest`）呼应：收割管"收"，播种袋管"种"，形成种田小闭环。定位是省点击次数的农具，**不替代骨粉、不自动补种**，需要玩家主动挥动。

### 1.2 行为

- 手持播种袋对任意方块右键：以点击位置为中心，在 **3×3 范围**内寻找可播种位置。
- **泛化种植（有机扩展）**：播种位置不限于耕地——逐格按"背包里有没有种子能在此存活"判定（canSurvive），因此**甘蔗（沙+水旁）、仙人掌（沙）、竹子、地狱疣（灵魂沙）自动兼容**：右键沙地/灵魂沙也能一片种下去，农具升级为"种植袋"。
- **潜行+右键 = 精准模式**：只种点击的那 1 格（留给梯田边缘、不规则小块地的细节操作）。
- 可播种位置条件：该格是耕地、上方是空气（或可被植物替换的植物/雪等——保守起见只认空气）。
- 种子来源：遍历玩家背包（含快捷栏，不含盔甲槽），取**第一种**能种在该位置的种子。
  - 种子判定（**26.2 实测：种子不再是 ItemNameBlockItem**，而是作物方块的 BlockItem——如 `WHEAT_SEEDS = BlockItem(Blocks.WHEAT)`，mcsrc `Items.java:1027` 已验证）：`item instanceof BlockItem`，且其方块 `defaultBlockState` 在目标格上方位置通过 `canSurvive`（含光照+基质检查，mcsrc `CropBlock.java:151` 已验证），且目标格可被替换（空气）。正是 canSurvive 泛化让甘蔗/仙人掌/竹子/地狱戊自动兼容。
  - 这保证泛用性：任何模组/数据包注册的同类作物方块自动兼容。
- 每个成功播种的位置消耗 1 个种子，种下对应作物（`defaultBlockState`）。
- 创造模式不消耗种子。
- **混合种植**：3×3 内逐格独立找种子——若背包有多种种子，会按遍历顺序种植，允许一次铺出混合田。

### 1.3 音效与粒子

| 事件 | 反馈 |
|---|---|
| 成功播种（整批一次） | **复用项目现有 `HarvestFx` 的种植音效模式**（`SoundEvents.CROP_PLANTED`，地狱疣换 `NETHER_WART_PLANTED` 分支，项目已验证可用），音高随播种数量微调（种得多音高略低，手感"扎实"） |
| 每格播种 | `HAPPY_VILLAGER` 绿色粒子 2-3 个 |
| 无种子/无可种位置 | 不播放声音、不挥臂（原版 use 返回 fail 的手感），避免"点了没反应还挥手"的错觉 |
| 使用 | 手臂挥动一次 |

### 1.4 物品属性

- `quirky:seed_pouch`：堆叠 1，无耐久（布制工具袋，不损耗），无附魔。
- tooltip 显示用法提示行（`tooltip.quirky.seed_pouch`：右键播种 3×3，潜行右键单格）。
- 贴图建议：棕色小布袋+露出的种子（先示意稿后落地，遵循贴图流程）。
- 合成：皮革 + 线×2 + 小麦种子（无序），便宜易得，符合农具定位。

### 1.5 边界场景清单

| 场景 | 行为 |
|---|---|
| 点击干耕地 vs 湿耕地 | 均可播种（与原版一致） |
| 甘蔗/仙人掌/竹子/地狱戊 | canSurvive 判定自动兼容，按种子自身规则找位置（如甘蔗需水旁） |
| 背包只够种 2/9 格 | 种能种的，剩余位置跳过，不报错 |
| 副手持播种袋、主手持其他 | 对耕地右键时副手物品正常触发（沿用原版 useOn 语义） |
| 潜行点击 | 精准模式只种 1 格，不扫描周围 |
| 3×3 内有非耕地/石头 | 跳过该格 |
| 对完全不可种植的方块（如石头）右键 | 无效果（不挥臂） |
| 与收割机制交互 | 收割补种是原地单格；播种袋是区域新种，互不冲突 |
| 满背包 | 不影响（播种只消耗不产出） |

### 1.6 配置

- `seedPouchEnabled`（bool，默认 true）
- `seedPouchRadius`（int，0-2 对应 1×1/3×3/5×5，默认 1 即 3×3）——给想更猛或更保守的玩家留口，半径参数同时用于扫描函数。

### 1.7 实现要点与风险（已验证锚点）

- 纯交互物品，无 mixin：`Item.useOn(UseOnContext)`（已验 Item.java:179）内完成扫描+种植+消耗；项目收割机制已验证 fabric `UseBlockCallback` 事件模式（HarvestHandler），两者不冲突（收割处理成熟作物，播种袋处理可种植位置）。
- 扫描与"选种子"逻辑抽成纯函数（输入：格子状态列表+背包快照；输出：每格种什么+消耗清单），便于单测。
- 风险点：直接用 `level.setBlock` 种作物（不走 BlockItem.place，避免上下文构造的客户端副作用），但必须 canSurvive 预检，否则作物会在下一 tick 被原版破坏逻辑打落。

### 1.8 验证

- 单测：扫描选种逻辑（多种种子混合、不足、无可种位置）。
- 手动：桌面客户端 3×3 播种、混合种子、创造模式、与收割连用。

## 2. 鱼饵球（Fish Bait）

### 2.1 定位

扔到水面化开，形成一片"打窝区"，区内浮漂咬钩更快。定位是**省等待时间的钓鱼辅助**，不提升渔获质量、不自动上鱼，保持钓鱼的手动节奏。

### 2.2 行为

- 新物品 `quirky:fish_bait`，堆叠 16，可投掷（同鸡蛋手感）。
- 落点判定：
  - **落在水面**：化开，生成一个不可见的**诱鱼区实体**（`quirky:bait_zone`），半径 **4 格**、持续 **90 秒**。
  - **雨天加成（有机扩展）**：降雨期间生成的区域持续 **150 秒**且气泡更密——与原版"雨天钓鱼更快"的设计态度一致，主题自洽；已存在的区域不追溯延长（生成时快照天气）。
  - **落在地面/方块**：碎裂消失（碎屑粒子+轻响），不生成区域。
- 诱鱼区效果：`FishingHook` 的服务器 tick 中，若浮漂位于任一诱鱼区内，`timeUntilLured` 倒计**额外再减 2**（原 -1 实测感知太弱，2026-08-04 强化；即咬钩等待速度约 ×3）。
  - **实现约束（历史 bug 教训）**：额外递减必须 clamp ≥1，不能 clamp 0——原版转换（timeUntilLured<=0 → timeUntilHooked）只在原版自身递减后触发；若额外递减把值打成 0，下一 tick 原版走 else 分支重掷 100-600、进度全部丢失，加速实际失效（用户实测"钓鱼速率没变"根因）。详见 `BaitZoneLogicTest.lureSequenceAcceleratesToThirdWithoutReroll`。
  - 二进制判定：在多个区域内不叠加（避免堆叠破坏平衡）。
  - 与诱饵附魔（lureSpeed）的关系：lureSpeed 是每次递减的基础步长，本效果是额外步长，二者相加不冲突，实测约为"再快一倍"，温和。
- 区域结束或玩家收竿重抛不影响区域本身（区域是独立实体）。

### 2.3 音效与粒子

| 事件 | 反馈 |
|---|---|
| 投掷 | `SoundEvents.SNOWBALL_THROW`（已验证） |
| 水面化开 | 小型水花（`SPLASH` 粒子）+ `SoundEvents.GENERIC_SPLASH`（已验证；音量 0.4） |
| 区域存在期间 | 水面偶发上浮 `BUBBLE` 气泡粒子，**气泡密度随剩余时间线性变稀**（不用 UI 就能直观看出"窝快散了"） |
| 地面碎裂 | `SoundEvents.ITEM_BREAK`（已验证）+ 棕色碎屑粒子 |

### 2.4 物品与配方

- 合成：小麦 + 腐肉（无序）→ 4 个鱼饵球。廉价、有"下脚料做饵"的叙事感。
- 贴图建议：一小团棕黄色碎饵（先示意稿后落地）。

### 2.5 边界场景清单

| 场景 | 行为 |
|---|---|
| 区域重叠 | 不叠加，效果相同 |
| 浮漂在区域边缘进出 | 每 tick 实时判定（AABB 包含检测），进出即时生效 |
| 诱鱼区所在区块卸载 | 实体随区块保存/恢复，倒计时以 tick 计，卸载期间不流逝（可接受，与实体语义一致） |
| 玩家跑远（>128 格） | 区域实体按常规规则卸载，回来仍在 |
| 投掷到陆地水域边缘 | 落点以实体落地的方块为准，水面判定=落点方块是水 |

### 2.6 配置

- `fishBaitEnabled`（bool，默认 true）
- `fishBaitDurationSeconds`（int，10-300，默认 90）——雨天自动 ×5/3（150s）
- `fishBaitRadius`（int，2-8，默认 4）

### 2.7 实现要点与风险（已验证锚点）

- Mixin 策略（已验 FishingHook 结构）：`FishingHook.tick()`（FishingHook.java:153）内分支链为 nibble → timeUntilHooked → timeUntilLured，递减语句 `timeUntilLured -= fishingSpeed`（局部变量 fishingSpeed 声明于 :299，字段 nibble/timeUntilHooked/timeUntilLured :64-66）。策略：@Shadow 三个字段，@Inject HEAD 快照"本 tick 是否执行递减分支"（nibble==0 && timeUntilHooked==0 && timeUntilLured>0），@Inject TAIL 若快照为真且浮漂在诱鱼区内 → 额外再减（clamp ≥1，理由见 §2.2 实现约束）。另：区内浮漂每 tick 25% 概率服务端冒泡（sendParticles BUBBLE），作为"生效中"的可见反馈。判定确定性：分支执行 ⇔ HEAD 条件成立。
- 区域判定性能：每浮漂每 tick 做一次 `level.getEntities(EntityType 过滤, AABB)`——浮漂数量极少，开销可忽略；不引入自定义 spatial 索引。
- 诱鱼区实体：无重力、无碰撞、不可见、tick 倒计时自毁，注册进 `ModEntities`。

### 2.8 验证

- 单测：区域包含判定、叠加不翻倍逻辑（纯函数）。
- 手动：桌面客户端实测打窝前后咬钩间隔对比（主观但明显）；陆地投掷碎裂分支。

## 3. 公共约定

- 新物品过 `quirky-new-item-checklist`；mixin 过 `quirky-mixin-runtime-audit`。
- 两项互不依赖，可并行开发。
- 非目标：不做自动播种机/自动钓鱼（平衡红线）、不做渔获表修改。
