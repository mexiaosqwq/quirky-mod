# 保留图腾（Totem of Holding）设计文档

日期：2026-08-02
状态：已确认（用户逐节批准）

## 1. 目标

模仿 Quark 模组的 Totem of Holding 机制：玩家死亡时，背包物品集中保存在死亡点的一个图腾实体中，方便跑尸取回——物品不散落一地、不 5 分钟消失。行为参考 Quark wiki（Oddities 页），按 Quirky 的"小机制 + 简单优先"原则做适配实现。

## 2. 范围

**做**：
- `TotemEntity` 自定义实体（生成 / 悬浮 / 无敌 / 击打取回）
- 死亡拦截 Mixin（`ServerPlayer.die` 中 `dropAllDeathLoot` 调用之前）
- 存储、取回、破裂逻辑（拆成可测纯函数）
- 图腾物品贴图与客户端渲染（贴图先示意后落地）
- 单元测试 + 桌面客户端手动验证

**不做（非目标）**：
- 灵魂指南针（Soul Compass）——后续迭代
- 经验值保存（保留原版惩罚）
- 配置界面
- 与 Curio/饰品槽兼容

## 3. 机制规格

### 3.1 触发条件（全部满足才生成图腾）

- 服务端玩家死亡
- 非创造模式、非旁观者
- 游戏规则 `keepInventory=false`
- **非 PVP 击杀**：伤害来源（`DamageSource.getEntity()`）不是玩家（含间接伤害：箭矢等弹射物的主人是玩家）
- 死亡位置：玩家死亡坐标；**掉进虚空 → 生成在 Y=0 处**

### 3.2 生成

- 死亡点上方约 0.5 格处悬浮，客户端轻微上下浮动动画
- **无敌**：免疫一切伤害（含环境伤害），无 despawn 计时，不会自然消失
- 存储内容：背包 41 槽全部非空物品（0-35 物品栏、36-39 盔甲、40 副手），**按原槽位记录**
- 一次死亡生成一个图腾
- 图腾实体数据随区块保存（服务器重启不丢失）

### 3.3 取回

- **任何玩家**（不限死亡者）近战击打图腾 **3 次**取回
- 第 3 次击打触发归还：物品**按原槽位**放回该玩家背包；背包放不下的物品**在图腾位置原地掉落**（不丢失）
- 归还完成后图腾实体移除，播放取回音效
- 附魔、自定义 NBT 等物品原样往返，无损耗

### 3.4 破裂规则

- 玩家死亡时，若该玩家已有**未取回**的图腾 → 旧图腾**破裂**：全部存储物品在旧图腾位置原地散落（恢复正常死亡效果），旧图腾移除
- 本次死亡**照常生成新图腾**（收本次背包）
- **物品守恒**：任何路径都不吞物品

## 4. 技术实现

### 4.1 死亡拦截点（已查证 26.2 源码）

```
ServerPlayer.die() → dropAllDeathLoot() → dropEquipment()
    → if (!keepInventory) inventory.dropAll()   ← 背包掉落发生在此
```

Mixin 注入 `ServerPlayer.die` 中 `dropAllDeathLoot(...)` 调用**之前**：判定触发 → 复制背包 41 槽到图腾 → 生成图腾实体 → 清空背包 → 原版 `dropAll()` 掉落空背包（无掉落物）。

### 4.2 数据存储

- 实体 NBT：`Items` ListTag，每项 `{Slot: int, Item: ItemStack}`（槽位编号 0-40）
- 手写序列化/反序列化，配往返单元测试

### 4.3 逻辑分层

| 单元 | 职责 |
|---|---|
| `TotemOfHoldingLogic`（纯静态，可测） | `shouldSpawnTotem(player, source)` / `collectInventory(player)` / `breakOldTotems(player, level)` / `restoreToPlayer(player, totem)` |
| `TotemEntity` | 实体行为（无 AI、无敌、击打计数） |
| `ServerPlayerMixin` | 拦截点，调用逻辑 |
| `TotemEntityRenderer`（客户端） | 悬浮渲染图腾物品模型 |

### 4.4 物品与贴图

- `quirky:totem_of_holding` 物品（用于实体渲染，也进创造页签供演示）
- 贴图 16x16，**先出预览图经用户确认后再落地**
- 渲染：实体渲染器直接渲染该物品的 ItemStack 模型，带浮动/旋转

### 4.5 测试

单元测试（`TotemOfHoldingLogicTest`）：
- 生成判定矩阵（PVP / 非 PVP / 创造 / keepInventory / 旁观者）
- 收集 41 槽（忽略空槽，槽位正确）
- NBT 往返无损（含带 NBT 的物品）
- 归还：背包有空位按原槽位还原；背包满 → 剩余物品返回待掉落列表
- 破裂规则：未取回再死 → 旧图腾破裂且新图腾照常生成

Mixin 拦截与实体行为依赖构建 + 桌面客户端手动验证（死亡 → 图腾 → 击打取回 → 破裂）。

## 5. 验收标准

1. 生存模式死亡 → 死亡点出现悬浮图腾，原背包物品**不**散落
2. 击打 3 次 → 物品按原槽位回背包；背包满时多余物品原地掉落
3. PVP 击杀 → 不生成图腾，正常掉落
4. 未取回再死 → 旧图腾破裂散落，新图腾照常生成
5. 虚空死亡 → 图腾生成在 Y=0
6. 图腾不受伤害、不消失（等 5 分钟仍在）
7. 物品（含附魔/自定义 NBT）往返无损

## 6. 风险与边界

- `ServerPlayer.die` Mixin 依赖 26.2 方法结构，版本升级需复查
- 大 NBT 物品（满背包附魔装备）序列化体积——往返测试兜底
- 多人：图腾可被其他玩家取走（Quark 原版行为，允许）
- 图腾生成后玩家立刻退出服务器 → 实体随区块保存 ✓
- 图腾在地狱/末地/下界对应维度生成（维度内死亡）✓

## 7. 已确认决策

| 决策点 | 结论 |
|---|---|
| 形态 | 自定义实体（非物品），死亡自动生成，无需携带 |
| 取回方式 | 击打 3 次，任何玩家可取 |
| 破裂规则 | 未取回再死 → 旧图腾破裂散落，物品守恒 |
| PVP 击杀 | 不生成图腾 |
| 灵魂指南针 | 不做（后续迭代） |
| 经验值 | 不保存 |
